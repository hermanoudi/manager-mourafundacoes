# P1 Fundação — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar o esqueleto do sistema de gestão em produção: API FastAPI + Postgres no Railway, PWA Next.js na Vercel, login com papéis, cadastro de usuários, clientes e perfuratrizes, utilizável no notebook, Galaxy S23 e iPhone 14 Pro.

**Architecture:** Monorepo com `backend/` (clean architecture: domain / application / infrastructure / interfaces/http) e `frontend/` (Next.js App Router). O navegador só fala com a origem da Vercel; `next.config` reescreve `/api/*` para a API no Railway, e a sessão é um cookie JWT `httpOnly` de primeira parte. Banco versionado só por Alembic; testes do backend rodam contra Postgres real (docker compose).

**Tech Stack:** Python 3.12, uv, FastAPI, SQLAlchemy 2 (async) + psycopg 3, Alembic, pydantic-settings, PyJWT, pwdlib[argon2], pytest + pytest-asyncio + httpx; Node 22, npm, Next.js (última estável, App Router, TypeScript), Tailwind CSS v4, TanStack Query v5, React Hook Form + zod, Vitest + Testing Library, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-09-sistema-gestao-design.md`

## Global Constraints

- Dinheiro/medidas: `Decimal` no Python, `NUMERIC` no banco, string no JSON (`"12.50"`); nunca `float`.
- Entrada numérica aceita vírgula decimal pt-BR (`"12,5"` → `Decimal("12.5")`).
- Banco: **somente Alembic**; nunca `Base.metadata.create_all`; toda migration tem `downgrade()`; teste falha se modelos divergirem das migrations.
- Interface em pt-BR; código, rotas, tabelas e campos em inglês.
- Papéis: `admin`, `office`, `operator` (exatamente esses valores).
- Fuso de negócio `America/Sao_Paulo`; timestamps `TIMESTAMPTZ` em UTC.
- Viewports-alvo: 360×780 (Galaxy S23), 393×852 (iPhone 14 Pro), 1280×800 (notebook); toque ≥44px; sem scroll horizontal.
- Segredos só via env (`SecretStr`); nunca commitar `.env`.
- Camadas: `domain/` só stdlib + pydantic; `application/` nunca importa `infrastructure/`.
- Commits em português: `tipo(escopo): descrição` (`feat`, `fix`, `chore`, `docs`, `test`).
- Rodar ruff só em `backend/src backend/tests backend/migrations backend/scripts` (nunca `ruff format` no repo — reformata `.md`).

## Review Focus

1. **CPF/CNPJ formatado ou alfanumérico** — `"12.345.678/0001-95"`, `"12345678000195"` e o CNPJ alfanumérico (`"12.ABC.345/01DE-35"`) devem validar; duplicidade detectada independente da máscara → teste em Task 3 e Task 5.
2. **Login no Safari/iOS** — cookie de sessão precisa sobreviver no WebKit; garantido pelo rewrite same-origin → teste Playwright no projeto `iphone-14-pro` (Task 9).
3. **Vírgula decimal do teclado do celular** — `max_depth_m = "22,5"` grava `22.50` → teste em Task 3 e Task 6.
4. **E-mail com maiúsculas/espaços no login** — `" Admin@Moura.com "` autentica o mesmo usuário que `admin@moura.com` → teste em Task 4.
5. **Dono se trancando para fora** — o único admin desativa ou rebaixa a si mesmo → 409 `last_admin` (Task 4). Também coberto: operador recebe 403 em clientes e não vê o menu (Tasks 5 e 9).

## API contract (usado por backend e frontend)

Todas as rotas sob `/api`. Erros: `{"detail": str, "code": str}`. Listas: `GET ?q=&page=1&page_size=20` → `{"items": [...], "total": int, "page": int, "page_size": int}` (`page_size` máx. 100).

| Método e rota | Papéis | Corpo / resposta |
|---|---|---|
| `GET /api/health` | público | `{"status":"ok"}` |
| `POST /api/auth/login` | público | `{email, password}` → 200 `UserOut` + `Set-Cookie: mg_session`; 401 `code=invalid_credentials` |
| `POST /api/auth/logout` | autenticado | 204, apaga cookie |
| `GET /api/auth/me` | autenticado | `UserOut`; 401 `code=not_authenticated` |
| `GET/POST /api/users`, `PATCH /api/users/{id}` | admin | `UserCreate{name,email,password,role}`, `UserUpdate{name?,role?,active?,password?}` |
| `GET/POST /api/customers`, `GET/PATCH /api/customers/{id}` | admin, office | `CustomerIn` / `CustomerOut` |
| `GET /api/drill-rigs`, `GET /api/drill-rigs/{id}` | todos | `DrillRigOut` |
| `POST /api/drill-rigs`, `PATCH /api/drill-rigs/{id}` | admin, office | `DrillRigIn` |

- `UserOut`: `{id:int, name, email, role, active}`.
- `CustomerIn`: `{document, name, trade_name?, state_registration?, municipal_registration?, email?, phone?, contact_name?, address:{zip_code, street, number, complement?, district, city, state, ibge_city_code?}, notes?, active?}`. `CustomerOut` = mesmo + `id`, `kind` (`"PF"|"PJ"`), `document` normalizado (só dígitos/letras maiúsculas), `created_at`.
- `DrillRigIn`: `{name, manufacturer?, model?, serial_number?, max_diameter_cm:int, max_depth_m:str, status:"active"|"maintenance"|"inactive", notes?}`. `DrillRigOut` = mesmo + `id`, `max_depth_m` como string `"22.00"`.
- Duplicidade: 409 `code=duplicate_document` (cliente), `code=duplicate_email` (usuário), `code=duplicate_rig_name` (perfuratriz). Desativar/rebaixar o último admin ativo: 409 `code=last_admin`. Validação: 422 `code=validation_error`. Sem papel: 403 `code=forbidden`. Inexistente: 404 `code=not_found`.
